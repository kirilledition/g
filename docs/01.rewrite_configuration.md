# Target design

## Principle

There should be exactly one source of truth for every user-configurable default:

```text
src/g/config.default.toml
```

Everything else should be metadata, parsing, validation, or derived state.

The current split should become:

```text
OptionSpec:
  describes option names, TOML path, type, support level, help text, default policy

config.default.toml:
  stores concrete default values for user-configurable options

config.py:
  loads defaults, merges overrides, validates, builds typed config

ExecutionPlan:
  converts typed config into immutable engine/run plan

engine/Rust/JAX:
  receives resolved values only; no hidden defaults
```

They are absent from `config.default.toml`, shown as commented examples in config templates, and validated as required at run time.

Examples:

If used in more than one place, define once and import. If used in both Python and Rust, add a parity test or generate both from a shared schema.

# Main architectural change

## Add default policy to `OptionSpec`

`OptionSpec` already centralizes option metadata: name, destination, support level, section, help text, CLI flags, value type, and accepted values.  It should also own the default policy and TOML mapping.

Add:

```python
class DefaultPolicy(enum.StrEnum):
    VALUE = "value"                  # must exist in config.default.toml
    ABSENT_IS_NONE = "absent_is_none" # omitted by default, normalizes to None/empty
    REQUIRED_AT_RUNTIME = "required_at_runtime"
    DERIVED = "derived"
    UNSUPPORTED = "unsupported"
```

Extend `OptionSpec`:

```python
@dataclass(frozen=True)
class OptionSpec:
    name: str                         # canonical option, e.g. "g-device"
    destination: str                  # Python/Click destination, e.g. "g_device"
    support_level: SupportLevel
    section: str                      # TOML section, e.g. "g.compute"
    help_text: str
    cli_flags: tuple[str, ...] = ()
    type: OptionValueType = OptionValueType.STRING
    multiple: bool = False
    is_flag: bool = False
    accepted_values: tuple[str, ...] = ()

    # New:
    toml_key: str | None = None       # e.g. "device" for canonical "g-device"
    default_policy: DefaultPolicy = DefaultPolicy.ABSENT_IS_NONE
    python_aliases: tuple[str, ...] = ()
```

Then:

```text
OptionSpec = metadata and mapping
config.default.toml = default values
```

Remove `OptionSpec.default`. Defaults do not belong there.

# Centralize TOML path mapping

Right now `flatten_g_section()` contains hardcoded aliases such as:

```python
"format": "g-output-format"
"chunks-per-arrow-file": "g-output-chunks-per-arrow-file"
"telemetry": "g-telemetry"
"log-file": "g-log-file"
```



That mapping should be generated from `OptionSpec`, not maintained manually.

Each `OptionSpec` should know:

```text
canonical name: g-output-format
section: g.output
toml_key: format
destination: g_output_format
```

Then the normalizer can build:

```python
OPTION_SPEC_BY_TOML_PATH = {
    ("g.output", "format"): OptionSpec("g-output-format", ...),
    ("g.output", "chunks-per-arrow-file"): OptionSpec("g-output-chunks-per-arrow-file", ...),
    ("g.diagnostics", "telemetry"): OptionSpec("g-telemetry", ...),
}
```

This removes another source of config drift.

# Refactor `config.py`

Current `config.py` loads `config.default.toml`, but then redefines many defaults as constants and fallback values.  It also uses many patterns like:

```python
normalized_options.get("g-firth-batch-size", DEFAULT_FIRTH_BATCH_SIZE)
```



After the refactor:

```text
No configurable DEFAULT_* constants in config.py.
No `.get(option, DEFAULT_...)` fallback for configurable values.
If a value has default_policy=VALUE, it must already be present from default.toml.
If a required default is missing, fail loudly.
```

Add helpers:

```python
def required_option(options: Mapping[str, Any], name: str) -> Any:
    if name not in options:
        raise ConfigError(f"Default config is missing required default option {name!r}.")
    return options[name]


def optional_option(options: Mapping[str, Any], name: str) -> Any | None:
    return options.get(name)
```

Then construction becomes:

```python
trait=TraitConfig(
    step=int(required_option(normalized_options, "step")),
    trait_type=trait_type,
    bsize=int(required_option(normalized_options, "bsize")),
    threads=optional_int(optional_option(normalized_options, "threads")),
)
```

For optional/no-default values:

```python
jax_cache_dir=path_or_none(optional_option(normalized_options, "g-jax-cache-dir"))
```

For values with defaults, never provide a Python fallback.

# Dataclass defaults

For the strongest design, make resolved config dataclasses explicit and remove tunable defaults from dataclass fields.

Instead of:

```python
@dataclass(frozen=True)
class GComputeConfig:
    device: types.Device = types.Device.CPU
    staging_depth: int = 1
```

use:

```python
@dataclass(frozen=True)
class GComputeConfig:
    device: types.Device
    staging_depth: int
    ...
```

Then add factories:

```python
@dataclass(frozen=True)
class RegenieConfig:
    ...

    @classmethod
    def default(cls) -> RegenieConfig:
        return from_option_layers(
            base_options=defaults.load_default_option_catalog().raw_toml,
            explicit_option_layers=(),
        )
```

For convenience, users call:

```python
RegenieConfig.from_options({...})
RegenieConfig.from_toml("run.toml")
RegenieConfig.default()
```

They should not rely on a no-arg dataclass constructor with hidden duplicated defaults.

If this is too disruptive for one agent task, use an intermediate step: keep dataclass defaults only for `None`/empty values and remove all tunable numeric/string defaults.

---

# Avoid env-only runtime tunables

Runtime behavior should not depend on Rust-owned environment variables when it
affects reproducibility or performance. Promote true user-facing tunables into
the shared config system, or remove the control surface.

The BGEN SIMD policy is not user-tunable. Rust uses AVX2 when the CPU supports
it and keeps scalar code only as the non-AVX2 fallback and correctness baseline.
Do not add a BGEN SIMD option unless new benchmark requirements justify a
dedicated reproducibility switch.

## Step 4 — Rewrite TOML flattening through `OptionSpec`

Replace hardcoded `flatten_g_section()` alias dictionaries with a generic function that resolves nested TOML keys using `OPTION_SPEC_BY_TOML_PATH`.

Current code has manually maintained alias maps for `[g.output]` and `[g.diagnostics]`.  Remove that duplication.

Pseudo-code:

```python
def flatten_option_dictionary(raw_options):
    flattened = {}
    for section, value in raw_options.items():
        if isinstance(value, dict):
            if section == "g":
                flatten_g_sections(value, flattened)
            else:
                flatten_section(section, value, flattened)
        else:
            flattened[normalize_option_name(section)] = value
    return flattened


def flatten_section(section, section_options, flattened):
    for toml_key, value in section_options.items():
        spec = options.OPTION_SPEC_BY_TOML_PATH.get((section, toml_key))
        if spec is None:
            flattened[f"{section}.{toml_key}"] = value  # for clear unknown error
        else:
            flattened[spec.name] = value
```

# One important warning

This task will touch many config tests. The agent should not “fix” tests by reintroducing constants. The invariant is:

```text
If a value is configurable and has a default, config.default.toml owns it.
```

Everything else should be derived from that file or explicitly classified as non-configurable.
