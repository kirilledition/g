# Remaining Rust Rewrite Opportunities

This note tracks only Rust rewrite candidates that are still worth considering.
Completed branch work is summarized in
`docs/04.native-planning-stats-handles.md`.

The best split remains:

```text
Rust:
  BGEN decode/preprocessing
  sample, covariate, phenotype, and prediction alignment primitives
  output writing/finalization
  manifest/resume validation
  low-overhead telemetry sinks

Python:
  public API
  CLI/TOML/config normalization
  execution planning
  JAX runtime setup
  high-level orchestration

JAX:
  multi-phenotype kernels
  binary Firth / approximate Firth
  dense linear algebra where batching is large enough
```

---

## 1. Quarantine row-major BGEN decode paths

Production association paths should stay variant-major. That is the natural
layout for per-variant association testing and for native preprocessing stats.

Recommended direction:

```text
production:
  run_bgen_variant_major_dosage_buffered_chunks(...)

legacy/test only:
  row-major chunk delivery
```

The cleanup should:

- Stop adding new features to row-major callbacks.
- Keep row-major tests only where they protect compatibility.
- Prefer device-side transpose only in code paths that truly require
  sample-major arrays.

Expected benefit:

- Fewer layout branches.
- Less callback and test surface.
- Easier SIMD and preprocessing maintenance.

---

## 2. Move prediction grouping closer to native planning

Grouped phenotype planning is native now, but prediction-source construction is
still Python-orchestrated after grouping. A cleaner end state is a native input
plan that records phenotype/covariate/sample grouping and prediction alignment
metadata together.

Target shape:

```rust
NativeRunInputPlan {
    groups: Vec<NativePhenotypeGroup>,
    prediction_alignment: Vec<NativePredictionAlignment>,
}
```

The first useful step is not to make Rust own execution. It is to have Rust
return enough planning metadata that Python can avoid rechecking alignment
contracts for each group.

Expected benefit:

- Less duplicated orchestration logic.
- Clearer compatibility checks between phenotype, covariate, sample, and
  prediction inputs.
- Easier manifest/debug reporting for grouped runs.

---

## 3. Move telemetry sink ownership to Rust

Current telemetry is split between Python event streams and Rust tracing. The
cleaner architecture is one Rust-owned physical sink:

```text
Rust owns the writer queue.
Rust tracing writes into it.
Python emits structured events through a cheap PyO3 call.
One writer owns the file.
```

Target API:

```text
_core.start_telemetry_session(config) -> TelemetrySession
_core.emit_python_event(session, event_dict_json)
_core.finish_telemetry_session(session)
```

Expected benefit:

- One queue policy.
- No confusing split between Python and Rust event files.
- Lower risk that production telemetry adds accidental synchronization or file
  overhead.

---

## 4. Add typed REGENIE text output in Rust, if compatibility output matters

Parquet/Arrow should remain the performance path. If drop-in REGENIE-compatible
text output becomes product priority, implement it as a typed Rust writer rather
than Python table formatting.

Target:

```rust
finalize_output_run_to_regenie_tsv(...)
```

Typed output columns:

```text
CHROM
GENPOS
ID
ALLELE0
ALLELE1
A1FREQ
INFO
BETA
SE
CHISQ
LOG10P
N
TEST
EXTRA
```

Expected benefit:

- REGENIE-compatible integration path.
- No generic Arrow cell-to-string conversion.
- Keeps output schema and formatting policy close to the native writer.

---

## 5. Keep trusted BGEN validation and SIMD policy native

Trusted BGEN validation and SIMD dispatch should remain self-contained in Rust.
AVX2 is the production SIMD target documented in
`docs/simd-optimization-reference.md`; AVX-512 and arbitrary selected-subset
SIMD should stay out unless new benchmarks justify them.

Potential follow-up:

```text
--g-bgen-simd auto|scalar|avx2
```

This should be treated as a benchmarking/reproducibility option, not a normal
user-facing tuning knob.

Expected benefit:

- Reproducible benchmark comparisons.
- Fewer accidental changes to trusted decode behavior.
- Clearer manifest/profile metadata for native decode policy.

---

## 6. Things to keep out of Rust

Keep these in Python:

- CLI and config normalization.
- TOML/default handling.
- JAX runtime setup.
- High-level execution orchestration.

Keep these in JAX:

- Binary Firth and approximate Firth kernels.
- Multi-phenotype dense linear algebra.

Avoid adding broad table/dataframe frameworks to the runtime core. The current
native direction should stay streaming parser plus typed arrays.

---

## Suggested Order

1. Quarantine row-major production paths.
2. Move prediction alignment metadata into native grouped planning.
3. Move telemetry physical sink ownership to Rust.
4. Add typed REGENIE text output only if compatibility output becomes a product
   requirement.
5. Add a SIMD dispatch override only for benchmark reproducibility.
