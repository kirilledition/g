# Remaining Rust Rewrite Opportunities

This is the canonical roadmap for the current Rust rewrite work. It includes
completed branch work, active implementation items, and deferred ideas.

The best split remains:

```text
Rust:
  BGEN decode/preprocessing
  sample, covariate, phenotype, and prediction alignment primitives
  output writing/finalization
  manifest/resume validation
  low-overhead telemetry sinks

Python:
  public API
  CLI/TOML/config normalization
  execution planning
  JAX runtime setup
  high-level orchestration

JAX:
  multi-phenotype kernels
  binary Firth / approximate Firth
  dense linear algebra where batching is large enough
```

## Completed

- Native grouped per-phenotype alignment planning is implemented.
- Grouped per-phenotype pipelines consume native-planned groups.
- Grouped alignment is exposed through `_core` and `_core.pyi`.
- Variant-major linear kernels can use native stats for high-frequency
  normalization while preserving matrix-derived fallback behavior.
- Rust, PyO3, and Python pipeline tests cover grouped alignment.
- Chunk-handle plumbing was evaluated. No public handle API was added because
  the current PyO3 writer path already builds `NativeChunkHandle` from `Arc`
  metadata/stat wrappers without cloning column vectors.
- Public row-major native delivery binding has been removed. Production BGEN
  dispatch uses variant-major dosage or variant-major packed delivery.
- Grouped per-phenotype run inputs now carry native-aligned multi-trait
  prediction sources prepared with the grouped alignment plan.
- Telemetry now writes Python lifecycle/progress events and Rust tracing into
  one Rust-owned JSONL stream.

---

## Completed: quarantine row-major BGEN decode paths

Production association paths should stay variant-major. That is the natural
layout for per-variant association testing and for native preprocessing stats.

Recommended direction:

```text
production:
  run_bgen_variant_major_dosage_buffered_chunks(...)

legacy/reference only:
  sample-major JAX compute kernels
```

The cleanup did:

- Remove public row-major native delivery bindings.
- Remove production dispatch fallback to row-major delivery.
- Keep sample-major compute tests only where they protect numerical parity.
- Prefer device-side transpose only in code paths that truly require
  sample-major arrays.

Expected benefit:

- Fewer layout branches.
- Less callback and test surface.
- Easier SIMD and preprocessing maintenance.

---

## Completed: move prediction grouping closer to native planning

Grouped phenotype planning is native, and grouped prediction-source
construction now happens before group execution. The current native input plan
records phenotype/covariate/sample grouping and carries aligned prediction
sources for each compatible group.

Target shape:

```rust
NativeRunInputPlan {
    groups: Vec<NativePhenotypeGroup>,
    prediction_sources: Vec<NativeMultiPredictionSource>,
}
```

Rust still does not own execution. It returns enough grouped run input state
that Python avoids constructing prediction sources inside the execution loop.

Expected benefit:

- Less duplicated orchestration logic.
- Clearer compatibility checks between phenotype, covariate, sample, and
  prediction inputs.
- Easier manifest/debug reporting for grouped runs.

---

## Completed: move telemetry sink ownership to Rust

Telemetry now uses one Rust-owned physical stream:

```text
Rust owns the writer queue.
Rust tracing writes into it.
Python emits structured events through a cheap PyO3 call.
One writer owns events.jsonl.
```

Target API:

```text
_core.NativeTelemetrySession(stream_file, queue_size, lossy)
session.emit_json_line(event_json)
session.finish()
```

Expected benefit:

- One queue policy.
- No confusing split between Python lifecycle, progress, and Rust event files.
- Lower risk that production telemetry adds accidental synchronization or file
  overhead.

## Deferred: typed REGENIE text output

Parquet/Arrow should remain the performance path. If drop-in REGENIE-compatible
text output becomes product priority, implement it as a typed Rust writer rather
than Python table formatting.

Target:

```rust
finalize_output_run_to_regenie_tsv(...)
```

Typed output columns:

```text
CHROM
GENPOS
ID
ALLELE0
ALLELE1
A1FREQ
INFO
BETA
SE
CHISQ
LOG10P
N
TEST
EXTRA
```

Expected benefit:

- REGENIE-compatible integration path.
- No generic Arrow cell-to-string conversion.
- Keeps output schema and formatting policy close to the native writer.

## Deferred: trusted BGEN validation and SIMD policy

Trusted BGEN validation and SIMD dispatch should remain self-contained in Rust.
AVX2 is the production SIMD target documented in
`docs/simd-optimization-reference.md`; AVX-512 and arbitrary selected-subset
SIMD should stay out unless new benchmarks justify them.

Runtime SIMD mode is intentionally not user-configurable. The production path
uses AVX2 when the CPU supports it and falls back to scalar code only for
portability and tests.

Expected benefit:

- Fewer accidental changes to trusted decode behavior.
- A single native decode policy without benchmark-only control surface.

---

## Things to keep out of Rust

Keep these in Python:

- CLI and config normalization.
- TOML/default handling.
- JAX runtime setup.
- High-level execution orchestration.

Keep these in JAX:

- Binary Firth and approximate Firth kernels.
- Multi-phenotype dense linear algebra.

Avoid adding broad table/dataframe frameworks to the runtime core. The current
native direction should stay streaming parser plus typed arrays.

---
