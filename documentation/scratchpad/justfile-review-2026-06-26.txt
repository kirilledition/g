Justfile review, 2026-06-26

Verdict:
Keep Justfile, but make it a thin, stable entrypoint layer. Move workflow truth
into saved tooling configs and typed tooling commands.

Problem:
The current Justfile grew from a convenient command launcher into a secondary
configuration system, cluster runner, benchmark router, docs surface, and
workflow state store. It contains too many environment variables, inline Hydra
overrides, inconsistent names, and direct app command lines.

Architecture rule:
Environment variables configure the machine.
Hydra configs configure the workflow.
Justfile recipes select the workflow.

Good parts to keep:
Common workflows have memorable names. Local, CI, CPU, GPU, SLURM, Rust,
coverage, docs, server setup, and Symphony lanes are useful. Generic SLURM
wrappers are useful as execution substrates.

Meaning that should move out of Justfile:
workflow configuration, benchmark grids, profiler selection, dataset selection,
machine profile selection, run naming, output directory policy, cluster
resource policy, build optimization policy, and long app command construction.

Target shape:
Use short Justfile recipes like:
profile-chr10-binary-gpu-full:
    uv run --no-sync python -m tooling.cli.profile_regenie2_deep --config-name profile_chr10_binary_gpu_full

Avoid long recipes that encode dataset, chromosome, BGEN prefix, prediction
lists, profiler toggles, budget overrides, and SLURM behavior as shell syntax.

Environment variable policy:
Keep environment variables for secrets, host-provided scheduler state, local
cache roots, local toolchain roots, and explicit one-off local path overrides.
Do not use environment variables as the primary source of truth for benchmark
grids, profiler modes, dataset identity, chromosome identity, production g
flags, output format, run semantics, or default SLURM resources for named
machine profiles. Those belong in tooling/configs/.

Saved configs to add:
profile_chr10_binary_gpu_full.yaml
profile_chr10_binary_gpu_smoke.yaml
profile_app_full.yaml
bench_binary_hot_gpu.yaml
bench_binary_hot_gpu_smoke.yaml
matrix_chr10.yaml
matrix_chr10_smoke.yaml
matrix_chr22.yaml
matrix_chr22_smoke.yaml

Naming direction:
Use domains such as dev, check, test, rust, data, bench, profile, matrix, perf,
release, server, symphony, and slurm. Prefer names such as:
dev-install
dev-install-perf
check-local
test-cpu
data-fetch
data-simulate
bench-bgen-reader
bench-binary-hot-gpu
profile-app-full
profile-chr10-binary-gpu-full
matrix-chr10
matrix-chr10-dry
matrix-chr10-smoke
perf-smoke
perf-cpu
perf-gpu
slurm-cpu-run
slurm-gpu-run

Avoid embedding node names such as landau in common recipe names. Put
machine=landau_gpu in saved configs or route through slurm-gpu-* wrappers.

Immediate changes:
Move deep_profile_landau_budget_overrides into Hydra configs. Replace
profile-chr10-gpu-binary-deep-landau with a saved-config recipe. Replace direct
regenie2-binary-gpu recipes with matrix/smoke configs. Add dev-install,
dev-install-perf, and dev-install-perf-max. Normalize recipe domains. Add a
justfile_check tooling guardrail. Document the environment-variable policy.

Migration phases:
1. Inventory and classify recipes as keep, rename, replace-with-config, legacy,
   or delete.
2. Add saved configs before editing recipes.
3. For a cautious migration, add new names first and later delete old aliases.
   For this implementation, use a full cutover and remove old public names.
4. Update documentation and Symphony workflow guidance.
5. Add guardrail checks for long inline Hydra override lists, stale --g-* flags,
   missing saved configs, documented recipe drift, invalid prefixes, and
   deprecated recipe names.
6. Delete legacy aliases after the cutover; in this implementation, old names
   are removed immediately and historical external flows are quarantined under
   legacy-* names.

Bottom line:
Justfile remains, but it becomes a readable menu of stable workflow names.
tooling/configs/ holds saved workflow truth. tooling/common/ and tooling/cli/
hold implementation. documentation/ holds command guidance.
